## 기설치 디자인 플러그인과의 역할 경계

이 PC에는 디자인 계열 플러그인이 이미 다수 설치되어 있다(frontend-design, insane-design, cc-design, ccpp의 ui-ux-pro-max·stitch 계열, ecc 프론트 스킬 — 세션 스킬 목록 실측). 중복 구현 금지:

- **이 킷 = 오케스트레이션 + 게이트 층**: 실행 순서 강제, 컴포넌트 매핑, 판정서, 완료 차단만 담당
- **기존 생성 품질 스킬 = 하위 부품**: 파이프라인 '생성' 단계에서 필요 시 호출 (예: frontend-design)
- 기존 플러그인이 이미 잘하는 것(디자인 감각·컴포넌트 생성 품질)을 킷 안에 다시 만들지 않는다

## 연결/동기화 스펙 (2026-07-20 18차 신설 — 설치 3형태 공존 보장)

> 마켓플레이스 플러그인·MCP 래퍼·스킬 어느 형태로 설치·실행해도 "원활하게 연결/동기화되어 동일하게 작동"을 구조로 보장하는 계약. 능력 정본은 01 §3 기능×표면 Parity 매트릭스.

1. **단일 출처 = `.design-kit/` 파일**: DB 없음(02 원칙) — 모든 표면이 같은 파일을 읽고, 쓰기는 코어 엔진만 한다. 별도 동기화 장치가 필요 없는 구조 자체가 동기화 보장책.
2. **실행 잠금 `.design-kit/.lock` — 구현 완료(2026-08-09)**: 파이프라인·대시보드 재검증·MCP 호출이 동시에 돌면 runs/ 순번·dev server 포트가 충돌 — "실행 1개" 원칙. 잠금 중 신규 실행 요청은 거부+안내. 비정상 종료 대비 stale 잠금은 기록된 PID 생존 확인 후 해제(자동 삭제 아님 — 오판 방지). `scripts/execution-lock.mjs`(`acquireLock`/`releaseLock`) + `verify-runner.mjs` 배선 — 02 결정 기록에 실측 근거(실제 프로세스 2개 동시 실행 테스트) 있음.
3. **버전 단일화**: plugin.json 버전 = 코어 엔진(scripts) = MCP 래퍼 버전 — 셋이 갈라지면 "설치했는데 다르게 동작" 사고(형제 플러그인 캐시 스냅샷 함정의 변형). 릴리스 시 plugin.json 한 곳만 올리고 나머지는 참조.
4. **설치 확인 기준**: 설치 형태별 "이 화면이 보이면 성공" 기준을 문서(01 §8)에 포함 — 플러그인=`/sodam-design-kit:setup` 명령 노출, MCP=`/mcp` 연결 목록 표시, 대시보드=127.0.0.1 페이지 로드.
5. **Figma 읽기는 항상 페이지/노드 직접 링크로 (2026-07-20 스파이크 실측 확정)**: 파일 전체를 열거(nodeId 생략 조회)하면 무료 Starter 플랜의 "파일당 3페이지" 제한에 걸려 일부 페이지가 안 보일 수 있음(실측 확인) — **반드시 사용자가 대상 페이지에서 직접 복사한 링크(node-id 포함)로 접근**. `/sodam-design-kit:pipeline`이 사용자에게 요구하는 입력은 파일 URL이 아니라 "대상 페이지/프레임의 공유 링크"로 명시할 것(02 KitConfig `figmaFileUrl` 설명 갱신 대상).
6. **Figma 이미지·SVG 에셋 URL은 7일 후 만료 (2026-07-20 스파이크 실측 확정)**: `get_design_context`가 반환하는 자산 URL은 임시(7일)이므로, 생성 코드에 그 URL을 그대로 박아넣지 말고 **즉시 다운로드해 프로젝트 자산 폴더(예: `public/design-kit-assets/`)에 저장 후 로컬 경로로 참조**. 이 규칙 없이 배포하면 7일 뒤 이미지가 깨지는 실사용 장애로 이어짐.

- [ ] **`--screenshotDir` 같은 산출물 저장 경로 인자는 상대경로로 넘어와도 `.design-kit/` 기준으로 정규화한다 (2026-08-04 실측 규칙 승격 — 실사용 M1 세션에서 발견, 같은 날 2라운드)**: 1라운드에서 "프로젝트 루트 기준"으로 정규화했더니, 곧이어 실제 새 세션 재시도에서 에이전트가 `.design-kit`를 안 붙인 상대경로를 넘겨 스크린샷이 `.design-kit/` 밖(형제 폴더)에 저장되고 `.gitignore` 보호 밖(git 추적 대상)으로 남는 2차 결함이 재현됐다(02 결정 기록). **기준점은 프로젝트 루트가 아니라 `.design-kit/` 그 자체여야 한다** — 이 킷의 모든 산출물(runs·reports·screenshots)의 유일한 정본 위치이자 `.gitignore`·보관 정리(`pruneScreenshots`)가 지켜보는 범위이기 때문. 새 CLI 옵션에 파일/폴더 경로 인자를 추가할 때마다 "상대경로로 오면 어디 기준으로 풀리는가"를 먼저 확인하고, 그 기준은 기본적으로 `.design-kit/`로 잡을 것
